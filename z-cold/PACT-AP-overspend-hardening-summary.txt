PACT — AP-overspend enforcement: external review summary
=======================================================
Date: 2026-08-10
Source: design note (PACT — AP-overspend enforcement) + public repo inspection
(schema.sql, rls-policies.sql, decision D-GH-2026-08-09-campaign-ap-budget-enforce)

CONSTRAINTS (unchanged)
- js/engine.js is the sole home of pricing logic. No SQL / second JS copy of compute().
- No custom backend. GitHub Pages + Supabase (PostgREST + RLS) only.
- characters.stats (full LOG + frozen costs) is client-writable by owner.
- characters.ap is the only server-authoritative number.
- Local file save must remain unrestricted.
- Client-side gate (enforceApBudget) already ships; it is a UX guard, not a trust boundary.

PROBLEM RESTATED
A player (or AI acting for them) can write any LOG to their own characters.stats row,
including one whose frozen costs sum above spendable AP, or one with deliberately
understated frozen costs. The existing client gate is bypassable via direct REST
or by editing the LOG before save.

RECOMMENDED HARDENING (priority order)

1. Narrow server-side frozen-cost sum check (best simple integrity available)
   - BEFORE INSERT/UPDATE trigger (or SECURITY DEFINER helper) on characters.
   - Sum the already-frozen cost fields present in the new LOG.
   - Compare against spendable = (ignore_player_ap ? 0 : player AP awards from LOG) + characters.ap.
   - Reject only when campaign-bound AND campaigns.rules.enforceApBudget is true.
   - Does NOT re-price anything → stays inside engine.js-only rule.
   - Limitation: client can still understate every frozen cost. Closes whole-LOG
     replacement / obviously-over-budget writes only. Still worth shipping.

2. CharGen draft-mode coverage without fighting exploratory UX
   - Do NOT hard-block every draft edit.
   - Add one shared post-mutation invariant (_cgAssertBudgetAfterMutation) called
     at the end of the existing delegation paths (or a single after-mutation helper).
   - Soft feedback while unlocked (banner / disable Lock button).
   - Hard block remains at lock-time and at cloud-save time (already shipped).
   - Avoids sprinkling checks into all four _cgWire*Delegation functions.

3. DM visibility (zero pricing logic)
   - Maintain or derive an is_over_budget indicator (sum of frozen costs vs spendable)
     visible in DM Console.
   - Optional: accept the write but set a flag / quarantine so the DM sees it;
     client then refuses further autosaves until cleared.
   - Cheap audit trail even when enforcement is off or bypassed.

4. Detectability of AI / bulk LOG rewrites
   - Keep / strengthen the existing unkeyed checksum; surface mismatches on load.
   - Heuristic or DM-visible flag for wholesale LOG replacement (many zero/round
     costs, sudden high-tier abilities, etc.).
   - Optional short history of LOG hashes + updated_at so DM Console can show
     “LOG changed dramatically since last award”.

5. Edge Function signer (only if project rules accept Edge Functions as “still Supabase”)
   - Client posts proposed LOG → Edge Function runs the same engine.js compute path
     → returns HMAC with server secret → trigger verifies signature on write.
   - Only path to real pricing integrity without a second independent implementation.
   - Heavier; leave for later unless the frozen-sum trigger proves insufficient.

AI / social angle (realistic attack is “ask an LLM to rewrite the LOG”)
- Well-behaved models already refuse clearly framed “forge costs / bypass budget” requests.
- Make silent rewriting leave footprints (checksums, rewrite heuristics, DM flags).
- Social process: require a short DM-visible note after large external rewrites;
  treat repeated blocked over-budget save attempts as audit events.

WHAT NOT TO DO
- Full server-side reimplementation of compute() pricing → rejected (engine.js rule).
- Hard-cap every CharGen draft edit → fights deliberate exploratory design.
- Keyed HMAC without a server secret → impossible under pure client + PostgREST.

SUGGESTED IMPLEMENTATION SEQUENCE
1. Ship the narrow frozen-cost sum trigger (pure SQL, low risk).
2. Add CharGen post-mutation invariant + keep lock-time / cloud-save hard blocks.
3. Add DM-visible over-budget indicator (and optional quarantine flag).
4. Strengthen checksum / rewrite detection for AI-assisted bulk edits.
5. Revisit Edge Function signer only if the above is still insufficient and rules allow it.

This package stays inside the stated architectural rules, raises the bar for both
casual UI bypass and AI-assisted LOG rewriting, and gives the DM eyes even when
the write succeeds.
